1. Set up Workbench

Workbench runs on Linux, macOS or Windows with WSL. Compilation requires a Linux x86_64 build host with the licensed SiMa ModelSDK. A Mac can open that host's Workbench in a browser and upload files from its own disk.

From a PoLiMa source checkout, using Python 3.10–3.12:

python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[deploy]"
polima workbench start
polima workbench status
polima workbench stop

The start command prints the browser address. For access from another computer on your trusted network, use --host 0.0.0.0 and the Workbench host's address. This server has no user-login system; keep it on a trusted network or use an SSH tunnel. A foreground session uses polima workbench serve and stops with Ctrl-C.

2. Import a model and dataset

In Models → Upload checkpoint, select the complete extracted checkpoint folder. Include config.json, all model .safetensors files and the processor, normalization and metadata files saved by training. Supported policies are ACT, GR00T N1.6 and GR00T N1.7. Detecting the folder does not establish compiler compatibility.

Use Upload dataset for an extracted LeRobot dataset. Browser uploads copy files to the Workbench host. Each upload is limited to 64 GiB. If files already exist on that host, use --models /path/to/checkpoints and enter the dataset path on the Compile page.

dataset/
  meta/
    info.json
    ... dataset metadata
  data/
    ... episode tables
  videos/
    ... videos referenced by those tables

Why is data required? PoLiMa's GR00T export uses observations to prepare model inputs, numerical reference checks and bundle metadata. Quantized compilation also uses calibration samples. The current GR00T pipeline requires a dataset even for BF16; this does not mean BF16 universally requires quantization calibration. Compilation does not retrain your policy.

What should I prepare? Start with the LeRobot dataset used to train the checkpoint. Keep its camera names, image dimensions, joint ordering, action representation and normalization metadata unchanged. GR00T currently accepts dataset formats v2.0 and v2.1, including meta/modality.json. Include all metadata and referenced episode/video files. A folder of unrelated images is insufficient.

For a smaller dataset, use your training pipeline's dataset tooling to export complete representative episodes with consistent metadata. Include the lighting, viewpoints, robot states and tasks the model will encounter. Do not remove videos or edit the dataset version label to bypass validation. PoLiMa does not currently provide a general dataset converter or a universally valid minimum sample count.

GR00T N1.7 minimum: the current exporter requires at least three complete episodes, each with 16 valid observations after accounting for image history and action horizon. Include their referenced videos and metadata.

Calibration and evaluation serve different purposes. Use separate held-out episodes to evaluate generalization. Numerical agreement with PyTorch measures fidelity; it is not robot task success.

3. Configure compilation

Install the licensed ModelSDK on the Linux build host. The compiler currently targets ModelSDK 2.1.3. Follow docs/install.md and docs/your-own-model.md in your checkout to prepare the model-specific dependencies and weights.

export MODEL_COMPILER_BIN=/path/to/model-compiler/bin
# For a GR00T N1.7 checkpoint:
export POLIMA_GROOT17_PYTHON=/path/to/groot-environment/bin/python
export POLIMA_GROOT17_SOURCE=/path/to/Isaac-GR00T

For N1.6 use POLIMA_GROOT16_PYTHON and POLIMA_GROOT16_SOURCE. These paths must point to your installed environment and matching source version; creating an empty folder is insufficient. N1.6 export needs its GPU dependencies. ACT needs the compatible LeRobot environment described in the installation guide.

Compiler dependencies are installed once on the Linux build host. A laptop used only to open Workbench and upload folders needs no ModelSDK or GR00T environment.

For N1.7, download the matching backbone using the instructions in docs/your-own-model.md, then set POLIMA_GROOT17_BACKBONE to its complete local directory. A cached Hub model ID is also accepted; its cache must remain accessible to Workbench.

Save the settings above once. This merges supplied paths into ~/.config/polima/config.json (or $XDG_CONFIG_HOME/polima/config.json) and preserves other settings:

python3 - <<'PYCONFIG'
import json, os
from pathlib import Path

path = Path(os.environ.get("XDG_CONFIG_HOME") or Path.home() / ".config") / "polima/config.json"
config = json.loads(path.read_text()) if path.exists() else {}
paths = config.setdefault("paths", {})
for key in ("groot16_python", "groot16_source", "groot17_python", "groot17_source", "groot17_backbone"):
    value = os.environ.get("POLIMA_" + key.upper())
    if value:
        paths[key] = value
if os.environ.get("MODEL_COMPILER_BIN"):
    paths["model_compiler_bin"] = os.environ["MODEL_COMPILER_BIN"]
path.parent.mkdir(parents=True, exist_ok=True)
path.write_text(json.dumps(config, indent=2) + "\n")
print(path)
PYCONFIG

Environment variables override saved values. Saved paths do not install dependencies. Restart Workbench on the build host to apply settings:

polima workbench stop
polima workbench start

Select the checkpoint and dataset, then choose Check prerequisites. These checks confirm basic paths and dataset structure; dependency compatibility, weights and model execution are checked during the build. Successful compilation does not prove robot readiness.

4. Install PoLiMa on your DevKit

Connecting over SSH does not install PoLiMa. On a new Modalix DevKit with supported SiMa runtime software, obtain the PoLiMa source checkout and run its installer on the DevKit:

git clone https://github.com/sima-neat/polima.git
cd polima
./scripts/install_polima_modalix.sh

Repository access and internet access are required. The installer prepares the Python environment, runtime and Studio. Review docs/install.md for the supported SDK versions and required privileges. With systemd available, it installs polima-studio.service; installing the Python package alone does not create this service. The installer leaves Studio stopped.

polima studio start
polima studio status
polima studio stop

Open the address printed by studio start from your laptop. If the service is missing, complete the DevKit installer and inspect its output. To run Studio in the foreground after its dependencies are installed, use polima studio serve; Ctrl-C stops it.

5. Connect and deploy

In Workbench → DevKits, enter username@devkit-address. SSH originates on the Workbench host, so that host must be able to reach the DevKit.

Use an SSH key already authorized on the DevKit, or enter its password to authorize the Workbench host's key. A key path refers to the Workbench host, not the laptop displaying the page. Password setup creates a key if necessary and adds its public key to the DevKit; passwords are not saved.

Permission denied means SSH rejected authentication. Check the username and password, or select the private key whose public key the DevKit trusts. A successful connection is saved only after SSH verification. Runtime installation and Studio availability are separate checks.

After installing PoLiMa, deploy a compiled bundle and open Studio. Configure cameras, robot calibration and safety settings before any robot run. Deployment alone does not validate arm motion.
